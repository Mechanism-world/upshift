# ATTRIBUTION — claudette's `toolloop` example as an upshift agent directory

## Upstream

- Repository: <https://github.com/AnswerDotAI/claudette> (315 stars, ~1.9k PyPI downloads/month)
- Commit extracted from: `f157e1d2ba2f57347b5ffe9bb929a137c4396ab9` (`claudette.__version__`
  = `0.3.16` at that commit; the released version at the time was 0.3.15)
- License: Apache-2.0 (`LICENSE` at the repo root). The tool docstrings, the orders/customers
  fixture and the three user requests below are reproduced from that Apache-2.0-licensed source.

The agent is claudette's own documented tool-loop example: `nbs/01_toolloop.ipynb`, the
"Problem setup" → "Tool loop" sections. Two in-memory dicts (cell 9) and three plain functions
over them (cell 12), driven by `Chat.toolloop` (`claudette/toolloop.py:23-47`), which calls
`Chat.__call__` → `Client.__call__` → `self.c.messages.create` (`claudette/core.py:288-290`).
That is upshift's `messages` endpoint.

## The two configuration questions, answered exactly

**Does the toolloop example set a system prompt?** **No.** Every cell that builds the chat
writes `Chat(model, tools=tools)` — cells 16, 22, 28, 33, and 47 for the async variant — with
no `sp=`. `Chat.__init__`'s `sp` default is `''` (`claudette/core.py:460`), it is stored as
`self.sp` (`core.py:475`), passed through `Chat.__call__` (`core.py:518`, `sp=self.sp`) and
placed on the wire unconditionally by `Client._precall`
(`core.py:264`, `kwargs |= dict(max_tokens=maxtok, system=sp, temperature=temp)`).
So the request carries `system: ""`. `system_prompt.txt` here is therefore an **empty file** —
that is not an omission, it is the extraction result.

(The one prompt string the loop does own, `_final_prompt` at `nbs/01_toolloop.ipynb` cell 25 /
`toolloop.py:18`, is sent as a *user* message on the last permitted step, not as a system
prompt. upshift's loop has no equivalent hook, so it is not reproduced — see deltas below.)

**Does it force `tool_choice`?** **No.** `Chat.__call__`'s `tool_choice` defaults to `None`
(`core.py:510`), `toolloop` never passes one, and `_precall` only emits the parameter when it is
truthy (`core.py:253`). So no `tool_choice` reaches the wire, and this agent does **not** hit
the documented `tool_choice: type "tool" and "any" are not supported for this model` 400
(DESIGN.md, `api_error_forced_tool_choice`).

Consequence, stated plainly: **this agent's Fable 5 → 5.1 exposure is behavioral only.** The
one documented 5.1 change it can meet is `serialized_tool_calls` — losing the ability to batch
independent tool calls in one turn — which is exactly what the `turns_at_most` checks in
`cases/cases.json` assert.

Worth recording for anyone else adapting claudette: `Client.structured` **does** force tool
choice — `res = self(msgs, tools=tools, tool_choice=tools, ...)` (`core.py:423`), and
`mk_tool_choice` (`core.py:244-246`) turns a truthy non-string into `{'type': 'any'}`. Any
claudette code path built on `structured()` is a hard 400 on both Fables. The toolloop example
is not such a path.

### The schemas were derived, not transcribed

`tools.json` is the output of importing the notebook's three function definitions and calling
`get_schema` on each — the same call `_precall` makes — then wrapping the result in upshift's
chat-style envelope (`{"type": "function", "function": {name, description, parameters}}`), which
`agent_loop.py` converts back to `{name, description, input_schema}` for the wire. The
derivation ran against the **clone at `f157e1d`** (put first on `sys.path`), with dependencies
from a throwaway venv: `fastcore==2.2.19`, `msglm==0.0.13`, `toolslm==0.3.48`, `anthropic==1.3.0`,
Python 3.12. `get_schema` lives in fastcore, so the exact bytes depend on the fastcore version
as well as on claudette — recorded here because the clone pins no upper bound.

Two things this produced that a transcription would have missed: the per-argument
`description`s that fastcore lifts from the numpydoc-style trailing comments (`# ID of the
customer`), and `cancel_order`'s description, which appends the **return** annotation:
`"Cancels an order based on the provided order ID\n\nReturns:\n- True if the cancellation is
successful (type: boolean)"`.

### Verified upstream finding: claudette cannot price a Fable

Read from the source, not run (no API call was made anywhere in this work). `model_types`
(`core.py:41-68`) maps every known model id to a pricing bucket; the Anthropic block is
`core.py:43-55` and stops at `claude-opus-4-6` / `claude-sonnet-4-6` / `claude-haiku-4-5`.
`Client.cost` is `self.use.cost(pricing[model_types[self.model]])` (`core.py:327`) and
`get_costs` opens with `costs = pricing[model_types[c.model]]` (`core.py:331`) — both index
`model_types` with the model string, with no `.get`, no default and no guard.

So on `claude-fable-5` or `claude-fable-5-1`, `chat.cost` (`core.py:482`) raises
`KeyError: 'claude-fable-5'`. It is not only an opt-in accessor: `Client._repr_markdown_`
(`core.py:346-358`) calls `get_costs(self)`, and `Chat._repr_markdown_` (`core.py:534`) calls
that in turn — so *displaying* a chat result in a notebook, which is how the toolloop docs are
written, raises. Fixing it is a one-line addition to `model_types` (plus a `pricing` bucket).
This is upstream's bug, orthogonal to the 5 → 5.1 migration, and it is recorded here rather
than worked around: `agent.json` does not go through claudette at all.

## Deltas from the real runtime

- **`temperature` is not sent.** claudette sends it *unconditionally* — `_precall` merges
  `temperature=temp` into every request (`core.py:264`) and `Chat`'s default is `temp=0`
  (`core.py:462`). Both Fables reject non-default sampling parameters with a 400 (DESIGN.md,
  `api_error_unsupported_sampling_params`), and `0` is not the default. Two consequences, both
  honest: (a) `params` here carries no `temperature`, because a 400 on **both** models measures
  nothing about the migration; (b) as written, **claudette cannot call either Fable at all**
  without a code change — an upstream fact, recorded, not repaired.
  (`upshift adapt` read `temperature: null` from rendered docs; the code at this commit says
  `0`. The null was wrong, the decision to drop it was right.)
- **The `_final_prompt` nudge is not reproduced.** `toolloop` injects
  `"You have no more tool uses. Please summarize your findings…"` as a user message on the
  second-to-last step (`toolloop.py:18`, `toolloop.py:38`). upshift's loop has no
  penultimate-turn hook; it simply stops at `max_turns`. No case here comes near 10 turns.
- **No `cont_pr`, no caching, no streaming.** `Chat(cache=False)` is the default
  (`core.py:464`); the notebook's streaming section (cells 41-42) is out of scope.
- **Tool-result shape.** claudette hands the function's return value to `mk_toolres`
  (`core.py:516`) which puts it in the `tool_result` block; upshift JSON-encodes whatever
  `Backend.execute` returns, so every reply here is wrapped as `{"result": <upstream return
  value>}`. Upstream's `"Customer not found"` / `"Order not found"` strings and its `False`
  travel unchanged inside `result`. Only failures upstream would raise on (unknown tool,
  non-object arguments, a missing argument) become `{"error": ...}` per the ADAPTER.md contract.
- **Aliasing is reconstructed.** Cell 9 builds `customers` out of the *same dict objects* that
  live in `orders` (`orders=[orders['O1'], orders['O2']]`), so cancelling O1 is visible through
  `get_customer_info('C1')`. JSON cannot express that sharing, so `backend.py` stores each
  customer's order list as ids and re-materializes it from the live `orders` dict on every read
  and in `state()`. Same observable behavior.
- **Model.** `agent.json` names `claude-fable-5`. The notebook uses `model = models[1]`
  (cell 6), which at this commit resolves to `claude-sonnet-4-6` (`core.py:73`, `models =
  all_models[:10]`, over the `model_types` order at `core.py:43-44`). The model is the variable
  under test.
- **`ns` / tool dispatch.** claudette calls the Python functions directly through
  `call_func`/`limit_ns`; upshift dispatches by name into `backend.py`. Same three functions,
  same semantics, no live namespace.

## The eval cases

Three are the notebook's own requests, verbatim:

| case | source |
| --- | --- |
| `customer_c1_email` | `"Can you tell me the email address for customer C1?"` — cells 18 and 28 |
| `cancel_all_orders_c1` | `"Please cancel all orders for customer C1 for me."` — cells 22, 33, 42 |
| `cancel_then_check_o2_status` | the same request followed by `"What is the status of order O2?"` — cell 35, which runs on the *same* chat as cell 33, so it is one two-segment case here |

Three more were written over the same data (`parallel_order_and_customer_lookup`,
`cancel_unknown_order`, `order_o1_details`). The checks are upshift's; claudette ships no eval
suite for this example — the notebook asserts nothing, it displays.

`sim.oracle_plan` blocks are ours: a replay script for `--provider sim`, whose final messages
contain the answers the case checks for, so a sim baseline satisfies `response_contains` by
construction. Sim runs validate the machinery, never the thesis (DESIGN.md); only
`--provider anthropic` runs are evidence about a model.

## Reproducing

```shell
uv run pytest -q tests/test_agents_claude_b.py
uv run upshift upgrade --agent agents/claudette-orders --provider sim \
    --baseline-model sim-fable-5 --candidate-model sim-fable-5-1 --tag cl-sim
```
