`sgpt`'s default (no `--shell`, no `--code`) agent is a plain OpenAI chat/completions
tool-calling agent — exactly upshift's v1 scope — so it can be expressed as an agent directory
without any framework shim.

Both files were generated by running upstream's code where that is side-effect free, and by
evaluating upstream's own literals where importing would write into `~/.config/shell_gpt`
(`sgpt/role.py` imports `sgpt.config`, whose import creates files). No rewording, no typo
fixes, no added text — the trailing `example`/`title` keys in the tool schema are pydantic's
and are sent to OpenAI exactly as they appear here.

## What was parameterized

`DEFAULT_ROLE` contains `{os}` and `{shell}` placeholders. Upstream fills them from
`SystemRole._os_name()` / `._shell_name()`, which return the `OS_NAME` and `SHELL_NAME` config
values verbatim whenever those are not `"auto"` (`sgpt/role.py` lines 113-133). We set them
through that same supported mechanism:

- `OS_NAME=Linux`
- `SHELL_NAME=bash`

Not for convenience: commands actually execute in a Linux container running bash (below), so
any other value would be the prompt lying to the model about its own environment.

## What was dropped

`sgpt/llm_functions/mac/apple_script.py` — the second bundled function — is macOS-only
(`osascript`). The sandbox is Linux, so shipping that tool would advertise a capability the
agent cannot have. `execute_shell_command` is the only tool, which also matches upstream's
`parallel_tool_calls=False`, one-tool-at-a-time behavior.

## Execution: reimplemented, sandboxed

Upstream's `Function.execute` runs the model's command on the user's own machine:

```python
process = subprocess.Popen(shell_command, shell=True, stdout=subprocess.PIPE,
                           stderr=subprocess.STDOUT)
output, _ = process.communicate()
return f"Exit code: {process.returncode}, Output:\n{output.decode()}"
```

`backend.py` reimplements that against a throwaway container over a per-episode file tree:

```
docker run --rm --network none --hostname shellbox --pids-limit 512 \
    -v <tmpdir>:/work -w /work -e TZ=UTC -e LC_ALL=C upshift-shellbox:latest bash -c <command>
```

Mirrored faithfully: the same shell (`bash -c`), the same combined stream (the child's stderr
*is* the stdout pipe, as upstream), the same exit-code envelope
`f"Exit code: {code}, Output:\n{output}"`.

### The result-shape delta

upstream appends the tool result as `{"role": "tool", "content": <that string>}` — a bare
string. upshift's `agent_loop._tool_result_item` JSON-encodes whatever `Backend.execute`
returns, so the closest honest mirror is a one-key dict and the model sees
`{"output": "Exit code: 0, Output:\n..."}` instead. One JSON wrapper, same bytes inside.
Backend-level failures (unknown tool, missing `shell_command`, timeout, sandbox unavailable)
come back as `{"error": ...}` per the ADAPTER.md contract; upstream has no equivalent — a
malformed call would raise inside `sgpt` and end the run.

### Other deltas from a real `sgpt` session

- **Container, not host shell.** No network (`--network none`), no `jq`, no package installs,
  no user home. `python:3.12-slim` and nothing added.
- **No streaming.** `sgpt` calls `completion(..., stream=True)` and prints deltas; upshift
  reads whole responses. Same request body otherwise.
- **Turn cap.** `sgpt` recurses through `get_completion` after every tool call with no bound;
  `agent.json` sets `max_turns: 6`.
- **No `tool_choice` / `parallel_tool_calls` in the request.** `agent.json` carries `params:
  {}` — deliberately. `sgpt` exposes no `reasoning_effort` setting at all, which is the whole
  point of this target: it is a real agent that cannot configure its way around the
  gpt-5.6-family chat/completions + function-tools break.
- **No response caching.** `sgpt` memoizes `get_completion`; every rep here is a fresh call.
- **Fixed clock.** Every fixture file and directory is stamped 2026-01-01 00:00:00 UTC, so
  `ls -l` is byte-identical across reps.

### State manifest, and one deliberate normalization

`Backend.state()` is a pure function of tree *contents* — never mtimes, never the temp
directory's name — exposing `paths`, `files` (sha256 + size per file), `files_text` and
`tree_sha256`.

`files_text` (files up to 200 bytes that decode as UTF-8) has **whitespace-stripped values**.
A case that asks the model to write a count into a file cannot know whether the shell will
produce `7` or `7\n`, and both are correct; stripping makes that check deterministic without
making it loose. The `files` and `tree_sha256` manifests stay byte-exact, so a case that means
to assert exact bytes still can.

## Reproducing

```shell
docker build -t upshift-shellbox:latest -f agents/shell_gpt/shellbox.Dockerfile agents/shell_gpt/
uv run pytest -q tests/test_shell_gpt_agent.py
```

The eval cases in `cases/cases.json` are upshift's, not upstream's — `sgpt` ships no eval
suite. They are grounded in the usage examples in upstream's README "Function calling"
section (listing a directory, and parsing a JSON file's email value without `jq`).
